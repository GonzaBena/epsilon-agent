# Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que la persona agregue «skills» (carpetas con un `SKILL.md`) que Epsilon usa con `/<skill>` o que la IA elige sola de una lista, con una página para administrarlas.

**Architecture:** Paquete nuevo `src/epsilon/skills/` (almacén, importación, uso en tiempo de ejecución, skills de fábrica) sin importar el núcleo. El núcleo (`core.py`) las despacha como comandos dinámicos, la IA las ve como el grupo `skills` (acción `usar`) más una lista en el prompt, y la web suma una API y la página `/skills` al estilo de Conectores. Nada se ejecuta: una skill es texto.

**Tech Stack:** Python 3 / FastAPI / pytest (sin llamar a modelos), HTML + JS plano en `channels/web_static/` (todo con `textContent`, CSP sin estilos en línea).

**Spec:** `docs/superpowers/specs/2026-10-25-skills-design.md`

## Global Constraints

- Código en inglés, mensajes al usuario en español rioplatense con voseo; en la UI «IA», no el nombre del modelo.
- Los datos viven en `DATA_DIR/skills/<nombre>/SKILL.md`; todo acceso por `notes.safe_path`, nunca armar rutas con texto de la persona.
- Nombre de skill (carpeta y comando): `^[a-z][a-z0-9_-]{0,31}$`.
- Solo la persona agrega, cambia, prende o borra skills; la IA no tiene ninguna herramienta que lo haga. La acción `skills.usar` es de solo lectura y arranca en `allow`.
- Se exige confirmación del servidor (`confirmed: true`) antes de guardar o cambiar el texto de una skill.
- `.zip`: anti zip-slip, solo extensiones de texto/datos, scripts nunca extraídos ni ejecutados (se avisa), topes de tamaño y de cantidad.
- Lo guardado y lo que vuelve a la IA pasa por `config.redact`; el contenido de una skill se rotula como dato de la persona y nunca concede permisos (`core._run_calls` sigue decidiendo).
- Los tests no llaman a un modelo ni a la red (la descarga por URL pasa por un único punto bloqueado en los tests).
- La web muestra todo con `textContent`; el menú izquierdo se repite en cada HTML y un test vigila que coincidan.
- Commits en inglés (`feat:`/`fix:`), SIN línea `Co-Authored-By`; nunca push; reiniciar el servicio tras tocar Python (`systemctl --user restart epsilon` y confirmar `is-active`).
- No leer ni mostrar `.env`.

## Review Focus

- Un `.zip` con `../../x`, ruta absoluta o enlace simbólico: no escribe nada fuera de `skills/<nombre>/` (Task 2).
- Un nombre que choca con un comando (`ver`, `ia`, `skills`) o con otra skill: se rechaza con motivo claro (Task 1 y 3).
- `SKILL.md` editado a mano en disco después de confirmar: queda sin usar (ni en la lista de la IA ni en `/<skill>`) hasta confirmar de nuevo (Task 1 y 3).
- Frontmatter roto, ausente, con BOM o saltos `\r\n`, o sin descripción: se rechaza o se normaliza sin romper (Task 1).
- URL a `localhost`/red local, redirección a una dirección privada o respuesta enorme: se rechaza antes de guardar nada (Task 2).
